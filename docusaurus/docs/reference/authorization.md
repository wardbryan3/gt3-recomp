---
title: Authorization and stop boundaries
---

The approved repository restructuring covers ownership, source/build/validation
organization, exact historical-context preservation and a bounded original-only
two-product checkpoint. It does **not** authorize subsystem expansion.

- `ps2run`: permanent enhancement-free generated reference, with reviewed rolling
  runtime/recompiler/platform updates and version-qualified evidence.
- `gt3-native`: original-equivalent defaults; no recovered/enhanced gameplay is
  installed by restructuring. Existing inherited optional presentation is not a
  new hardware qualification.
- Recovered/Modernized/Enhanced implementations require explicit product approval,
  independently of proof. Queue entries and former Frozen status are not permission.
- New replacement scope requires independent original oracle, exact differential,
  ABI and dynamic-cost tests, build/runtime gates, profile guards, observable tested
  fallback with exit criteria, and enabled/disabled/trace-only live verification.
- No physical adapter, FFB, AI/reset/step, replay format, physics retune or new
  recovery/promotion is authorized here. Playable/headless must not fork simulation.
- No commit, push, archive deletion or installation of game hooks is implicit in
  a restructuring checkpoint.

Retain failed attempts, protected inputs and exact original source contexts.
Do not weaken tests, rewrite historical hashes or silently skip missing private
artifacts. A new candidate does not renew stale product approval.
